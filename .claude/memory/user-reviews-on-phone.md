Review material is read mostly on a phone.

**Why:** a page that can be commented on from a phone is easier to review than a local Markdown file, and screenshots after each milestone show that development continues.

**How to apply:**

- Any doc, status or review that has to be read goes out as a commentable HTML page; reply with the link and never point at local .md paths. The links are kept outside the repository.
- After every milestone (and at major wave merges with visible UI or CLI output), run the app and send screenshots, in the dark theme as well as the light one.
- Keep chat replies short; cite feature IDs (for example SEC-04).
