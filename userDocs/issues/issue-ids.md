# Issue IDs

Every issue has an ID that you can say aloud and write in a message: the short name of its project, a dash and a code.

| Mode | Example | Good to know |
|------|---------|--------------|
| **Random IDs** | `WEB-K7Q2X` | Five letters and digits (4 to 8 if the administrators ask for it), from an alphabet without letters that look alike. The ID does not tell how many issues there are or how fast they come. |
| **Counting IDs** | `WEB-142` | Easy to say aloud. Anybody who sees two IDs a few weeks apart can tell how much work happens in the project. |

New projects use the choice of the organization, which starts as **Random IDs**. A project can choose for itself in *Project settings*, under "Issue IDs"; the people who may change the settings of the project (normally the project leads) can do that. A project inside another follows the project above it until it chooses.

## When the mode changes

When a project changes from one mode to the other, **every issue of the project gets a new ID**. The old IDs keep working: opening `WEB-K7Q2X` shows the issue under its new ID, and the address bar shows the new one. So links in messages, documents and other issues never break.

The same holds when the short name of a project changes: the old short name stays with the project, and `OLD-142` opens the same issue as `NEW-142`.

An ID that was given out is never given out again in its project, not even to another issue.

The organization's choice is a default for new issues: changing it does not change the IDs of issues that exist.
